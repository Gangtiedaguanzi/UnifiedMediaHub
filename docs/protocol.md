### Edge bridge threat model (F2, preview35)

In raw mode the page and userscript share a realm and built-ins. **The pairing token is not confidential from douyin.com page scripts.** Early capture reduces some later prototype/API replacement risks, but injection order, pre-existing hooks, prompts, extension behavior and shared-realm capabilities remain outside this guarantee. js is accepted for compatibility without claiming a stronger boundary. A page may forge or alter snapshots. Imported content is untrusted, not account authentication or user consent to download.

Defense layers and corresponding offline evidence:

- Any Origin header, including an empty one, is rejected; no CORS/OPTIONS. Cross-origin web fetch/XHR POSTs from douyin.com to loopback carry Origin or are blocked by browser policy; custom-token JSON requests also need preflight. It is incorrect to say every web request carries Origin. Tests: BridgeEndpointTests.DouyinOriginIsForbiddenEvenWithValidPairing (403/origin_rejected, zero imports), EndpointGuardsTokenOriginSizeJsonAndLifecycle and ParserRejectsSmugglingOriginAndForeignHostWithoutCors. This cannot stop a privileged extension request or local client without Origin.
- Exact loopback Host whitelist and strict parser: ParserRejectsSmugglingOriginAndForeignHostWithoutCors. The IPv4 listener stays master/feature-gated; repeated-stop and restart tests cover retirement.
- Script metadata @connect localhost limits extension request permission; runtime destination is fixed localhost + validated port. bridge-userscript raw/js controller tests verify destination, anonymous mode, no automatic request or token read. Metadata permission enforcement itself needs live Tampermonkey acceptance.
- Initial and every redirected media URL must be HTTPS on approved Douyin/CDN hosts: bridge-import rejection tests and bridge-download redirect test. This limits transfer destinations, not the trustworthiness of CDN content.
- Import only builds a partial list; download requires a separate manager action. BridgeHarness checks HTTP import produces rows without automatic download; Core mismatch-confirmation tests remain. A malicious same-page script may still submit unwanted bounded lists while the bridge is enabled.
- Bounds: 1000 works, 256KiB pruned raw work (oversized markers count as slots), 8MiB payload/cache, 64-depth Core JSON, 512KiB bridge-import item/64KiB other events, one import/eight connections/timeouts. bridge-userscript aggregate-budget tests, bridge-import size/count tests and BridgeEndpointTests cover these. These are not a total-process memory cap.

Pairing filters accidental requests and local clients that do not know the token; it does not protect against malicious same-page scripts, privileged extensions, or same-user malware able to access/decrypt local storage. Loopback/Origin/Host are request barriers, not proof of human intent. No credentials are intentionally written to DOM/window/postMessage/logs, but do not describe the token as leak-proof. Keep bridge off when unused; token rotation invalidates future authorization.

It emits authenticated `account` then only validated `folder` metadata, never media `item`/`receipt`. `WorkerFolder` has string `Id` (ASCII letters/digits/underscore/hyphen,1–128), nonempty `Title` (at most256 characters, no controls), and nullable nonnegative safe-integer `ItemCount`. ## Worker transport

One Node worker per operation, launched by C# into a Windows Job before first request is sent. Worker must not import-launch engines or browser until valid first request. stdin/stdout are UTF-8 JSON lines, stdout exclusively protocol; diagnostics stderr bounded and redact credential-looking values. stdin EOF means cancel/exit.

First stdin line:
`{version:1,requestId,operation:'login'|'loginQr'|'scan'|'download'|'listChats'|'listFolders',source:SourceRequest,items?:ContentItem[],paths:{dataRoot,downloadRoot,category?:string,browserExecutable,engineRoot},maxConcurrentDownloads:2}`.

Subsequent controls: `{command:'cancel'}`, `{command:'finish-login'}`, `{command:'input',inputId:'<current worker UUID>',text:'...'}` (TG login only, never log text), `{command:'resend',inputId:'<current worker UUID>'}` (explicit TG code resend only), `{command:'continue'}` only after explicit user action. TG controls must match the currently waiting prompt; stale controls cannot consume its successor. Worker does not auto-retry verification barriers. Cancellation must close browser and child processes in finally. Core closes Job if grace 5 seconds expires.

## Process API (namespace UnifiedMediaHub.Core.Runtime)

`OwnedWorkerSession.StartAsync(WorkerLaunchOptions options,WorkerRequest request,CancellationToken cancellationToken=default):Task<OwnedWorkerSession>`; options has `ExecutablePath`, `WorkerScriptPath`, `WorkingDirectory`, `Environment` dictionary, `ShutdownTimeout` default5s.
Session exposes `ProcessId`, `Completion:Task<int>`, `ReadEventsAsync(CancellationToken):IAsyncEnumerable<WorkerEvent>`, `SendControlAsync(object,CancellationToken)`, `StopAsync(CancellationToken)`, `IAsyncDisposable`. Async event delivery starts immediately without dropping early events; unknown fields ignored, malformed lines fail with bounded diagnostics. First request sent only after assign to kill-on-close Job. No global process name kills. On parent shutdown all sessions disposed.

Host resource measurement is separate from the worker JSON protocol. `IResourceWorkerRunner.RunWithResourcesAsync(request,emit,Action<ResourceMetrics>,cancellationToken)` is implemented by OwnedWorkerRunner and the installed ReleaseWorker bridge. Session StartAsync accepts an optional final observer and exposes an immutable Resources snapshot. One immediate sample and subsequent1second samples enumerate only the exact Windows Job, at most512PIDs and2buffer-growth retries. Membership and memory queries use the same opened process handle. A missing/failed process makes the current aggregate unknown/incomplete; it must not appear as zero or a partial total. Record private commit and working-set sum separately. Shared pages can be counted more than once, and sampled peaks are lower bounds on instantaneous peaks.

Sampler cancellation is awaited before the shared Job-release path closes its handle, on normal completion, protocol failure, write cancellation, stop and disposal. The release task never awaits Completion. GUI self-memory is measured by the same active sampler, displayed separately with its observation time, and not persisted. No idle sampler or external service is added.

The host coordinator supplies a fresh OperationId per Submit; each serialized worker batch retains its own RequestId. Ignore stale/mismatched or post-final callbacks. Cross-batch peaks use max, never sum; unsampled batches preserve incomplete coverage. Only final request summaries are written on the serial coordinator path to auxiliary `job_resources(job_id,request_id,operation,started_at,finished_at,sample_count,incomplete_count,peak_process_count,peak_private_commit,peak_working_set,operation_id)`, primary key `(job_id,request_id)`. The original eight-column jobs table is unchanged. Current samples, PID lists, process names, command lines, account/source identifiers and GUI memory are not stored in this table. A resource-summary write failure shows the fixed warning `资源记录未保存` without changing the media outcome. UI caches the latest operation group and labels historical samples; zero-worker reuse does not create an invented sample. Abrupt host failure may lose an unfinished resource summary.

## Host scan checkpoints

Preview25 adds a host-owned generation plus exact request binding, only for operation `scan`; fixed phase/terminal enums and successful unique item counts. Auxiliary `scan_progress(job_id,generation,request_id,phase,committed_unique_item_count,observed_current,total,observed_rounds,observed_pages,updated_at,terminal_state)` has primary key `(job_id,generation)`; jobs remains eight columns. It retains bounded numeric observations and checkpoint time, never raw cursors, event text or source/account metadata. Counts advance only after successful content Upsert. Initial, first item, waiting and terminal states flush immediately; other writes are throttled to one per second. Ordinary write failure preserves the prior durable checkpoint with a visible fixed warning; SQLite FULL also sets current state to failed and retains the existing stop-all behavior. Finalization uses host terminal state and guarantees active/Done cleanup without a last database read. Reopen marks running checkpoints interrupted, preserves the last successful checkpoint timestamp and starts nothing. Rescan is a new generation over the original source, not service-cursor continuation. Existing adapters do not report reliable page/round counts; these remain unknown. ## Installed package layout (controller ruling, 2026-10-24)

- Install root `<install>` (chosen at packaging time) retains the assessment, user-facing launcher/shortcut, `CURRENT.txt`, `data`, and `releases/<version>`.
- Each versioned release is self-contained: WPF executable/DLLs, `worker/src`, `worker/node_modules`, `runtime/node/node.exe` plus license, `runtime/engines/{gallery-dl,tdl}`, selected `runtime/browsers/chromium-1248` and required licenses. Development npm, SDK, source caches and duplicate headless browser are excluded.

- Standard shortcut starts the release's GUI executable with explicit `--data-root <install>\data`. No terminal window and no startup registration. From preview30, a direct executable under `install/releases/version` also defaults to `install/data`; an executable elsewhere defaults to adjacent `data`, and explicit `--data-root` takes priority. Existing alternative roots are not relocated or merged; the actual data location remains visible.
- The database and account/private session data live in `data/private`; settings without credentials in `data/settings.json`; sanitized bounded logs/reports in `data/logs` or user-selected export.
- The WPF host must secure the private directory ACL before saving a job's signed source URL or any credentials. Use Windows APIs; opening app with master off must not launch Node/engines/browser just to establish privacy.
- `--smoke-test` accepts a test-only output directory and uses synthetic local data; no platform network or account access. It must exercise real UI handlers, render an image of the actual WPF view, exit cleanly and clearly label fixture output.
- Updates stage a new release and switch the pointer/shortcut only after validation. Never overwrite existing private data, existing releases or prior download folders. First release is a locally verified preview until live platform cases pass; status terminology must reflect that boundary.
- First-release scope ruling: the user-facing .lnk directly identifies the executable. CURRENT.txt is a validated record of the most recently packaged release, not an executable launcher instruction and not an automatic update service. The packaging script verifies both after writing them and preserves previous files/backups on failure; no native dynamic launcher or background updater is required for v1.

## Download resume and selection clarification
For download requests, a `ContentItem` with `MediaResolved=true` carries the explicit allowed set of stable Media indices. The coordinator may remove assets whose stored receipt still verifies. A fresh detail fetch must not broaden that set. An unresolved item may discover its full media set; emit the resolved item before transfers so later retries know the stable assets. Never convert partial-gallery retry into whole-gallery re-download. Coordinator may batch selected items by serialized request size under the transport's 16 Mi character request bound; logical job selection/status/completeness persist across batches, and master-off/cancel prevents starting the next batch.
Concrete transport caps: C# first request 16 Mi UTF-16 chars, Node first request 16 MiB UTF-8 bytes; coordinator targets at most 8 MiB serialized UTF-8 per batch and respects both. Resolved item with empty Media never expands to all media.

## Account binding and preview ownership
Private-source jobs bind Source.AccountId to a verified account observed during scan. Worker adapters must compare a nonempty bound AccountId with current verified identity before emitting private list items or transferring their media; mismatched/unknown identity returns needs_action without silently rebinding. Emit account metadata for host persistence. Saved credentials and last-checked badges are not current identity proof. The coordinator persists this binding and preserves it on resume; a different login requires an explicit new source scan/job.

ThumbnailUrl may be an HTTPS image URL or a bounded data:image/jpeg;base64 or data:image/png;base64 inline thumbnail (at most 24 KiB decoded). No arbitrary local-file URI from adapters is accepted. Host-owned managed HTTP preview work is allowed only during an explicit enabled preview operation, is centrally tracked/cancelled on stop/off/close, and sends no platform cookies. Cached previews can be displayed offline. Use bounded concurrency, decode size and cache (default 128 MiB), with manual cleanup restricted to this application's cache; never download complete originals merely to manufacture a preview. Telegram may provide inline stripped/cached thumbnails from its already-exported metadata; missing preview bytes get a clear placeholder.

AuthorUrl permits the approved single-work-to-author-source action when reliable metadata exists. Derive only from the work's actual author handle/ID, never display nickname or authenticated Source.AccountId. It must classify as a profile on the item's same platform under the exact host/path allowlist. Host validates before offering an explicit new-source scan action; no automatic profile scan/download.
